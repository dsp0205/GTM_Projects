# Automated QBR Presentation Engine

A reporting workflow that turns customer usage and account data into a structured quarterly business review presentation.

The project separates metric calculation from narrative generation and presentation, so business figures are computed deterministically before they are used in the executive summary.

## Workflow

1. Load account and product-usage data.
2. Calculate quarterly usage, adoption, time savings, estimated value, ROI and payback.
3. Pass the resulting facts to a narrative layer.
4. Optionally use an LLM to write a concise executive summary using only supplied fact IDs.
5. Validate generated text so it cannot introduce unsupported numbers.
6. Build a PowerPoint draft and a separate review checklist.

## Key design choices

- **Deterministic calculations:** business metrics are calculated in Python, not generated by the language model.
- **Constrained narrative:** the model references approved fact IDs instead of inventing values.
- **Output validation:** generated text is checked for unknown placeholders and unsupported digits.
- **Human review:** the deck is saved as a draft alongside a checklist for final review.

## Files

- `build_qbr.py` – orchestrates the QBR generation workflow.
- `metrics.py` – calculates the account-level business metrics.
- `narrative.py` – generates and validates the executive summary.
- `deck.py` – builds the PowerPoint presentation.
- `make_data.py` – creates sample account and usage data.
- `finalize.py` – supporting finalization workflow.
- `test_narrative.py` – narrative validation tests.

## Tech stack

Python · Pandas · python-pptx · Anthropic API · Pydantic

## Design focus

The presentation layer can use AI to make the story easier to read, but the underlying business numbers remain tied to deterministic calculations. This keeps the QBR useful to customer-facing teams without handing control of financial metrics to a language model.
